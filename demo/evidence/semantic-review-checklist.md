# 语义复核人工验收清单

语义模型的措辞可以不同，验收时检查判断依据和动作类型，不要求逐字匹配。

| 场景 | 预期行为 | 核验依据 |
|---|---|---|
| 无信息量的开场套话 | 建议删除或直接进入结论 | 删除后不损失事实 |
| `全链路`、`赋能`、`闭环`连用 | REWRITE 为具体动作，不能只换同义套话 | 原文没有说明被赋能对象和闭环环节 |
| `原先`、`经过讨论`、`改为` | 指出这是过程痕迹，成稿应直接写当前 20 秒基线 | `workspace/evidence/product-baseline.md` |
| `大概`修饰发布日期 | VERIFY 后可改为明确日期 | 产品基线记录为 2026 年 10 月 15 日 |
| `仍然支持 Windows 10` | VERIFY 或 ASK，不应直接保留为事实 | 产品基线的最低平台是 Windows 11 23H2 |
| `可能低于 2 秒` | 区分门槛与实测值；可引用 1.82 秒结果改写 | `workspace/evidence/acceptance-results.txt` |
| `先……再……` | KEEP；当前句已经给出完整顺序和条件 | 产品基线中的灰度策略 |
| 固定冗余和重复词 | REWRITE，分别改为更短表达并去掉重复 | 不改变事实含义 |

还应确认以下界面行为：

- 未进行语义复核、复核完成但无改动、复核失败三种状态可区分。
- 每条改写均显示原因、原文和建议文本。
- 全文核对可按正文顺序导航，并能撤销后恢复。
- 普通打开文件和工作区文件可使用“保存”；粘贴或拖入文本只能“另存为”。
- 原文件被外部程序修改后，“保存”应拒绝覆盖。
