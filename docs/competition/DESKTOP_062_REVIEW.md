# 0.6.2 连接恢复、流式输出与 ASK 闭环验收

2026-09-09，Windows 11 原生打包应用，用户现有全局代理环境。此次针对用户截图中的连接失败及缺少 ASK 输入流程，不能用之前版本的部分成功替代本次验证。

## 修复与边界

- 默认服务为 `https://api.deepseek.com`，模型 `deepseek-v4-flash`；密钥只在内存中。
- 旧桌面流式路径将 90 秒配置硬缩短为 15 秒，所有网络异常又被合并成通用错误。已用离线 transport 模拟复现相同提示，并去掉隐藏的 15 秒限制。截图中的实际失败没有底层异常记录，因此不能断言是超时还是代理故障。
- 按连续无数据计时：默认 90 秒，SSE 数据及心跳刷新计时；有持续输出时不因超过 90 秒而失败。短文保留 300 秒总运行上限，长文保留每批 120 秒预算。可随时取消，未退出的底层连接数量受独立上限约束。
- 前端逐步展示公开的结论摘要，明确标注为未校验预览；只有完整结果通过校验后才产生修改建议。不展示或留存模型内部思维链。
- ASK 标记为“待补充”，提供输入框和直接跳转入口；VERIFY 也可补充核实结果。只发送与该问题相关的最多 2000 字原文片段、新输入最多 2000 字、累计作者信息最多 4000 字，使用一个模型请求生成一条建议。定位不唯一、越界、无改动、格式错误均明确报错；失败/取消保留草稿。信息不足时可继续追问。
- 长文先完成剩余段落再补充，避免续查覆盖作者新建议。正文变化时旧结果不能应用。生成后定位到该条 diff，仍需明确采纳，既有无关确认结果保留。

## 实测后继续修正

原生操作发现长理由会把输入框挤到下方，且生成后的列表从第一条显示，尽管内部已选中目标。已增加“补充信息 ↓”入口、拓宽结论面板，并让 ASK 成功后直接进入选中建议的全文 diff 核对模式，扩大 diff 可视区域。这些变化已有真实 Vue 集成回归；最终包 `dist-0.6.2-final2` 自检返回0。

独立子agent从首页实际操作最终 Windows 包，完成离线示例、逐条diff、待补充入口、定位并输入虚构信息，确认离线模式按钮禁用且有明确原因，补验通过。[步骤与原生UIA证据](../../demo/evidence/native-062-final-layout.txt)。1280×752窗口下详情区域仍较矮，定位输入框后需要再滚一下看提交按钮，记录为非阻塞体验摩擦。此轮不调用模型，不与上面的真实模型E2E混同。

后续只读审查发现同一行的宽范围改写可能与既有采纳重叠，现将模型返回内容缩小到实际变化片段，并在前端提交状态前检查与已采纳建议的冲突；冲突时保留全部原有决定和输入。回归直接重放本次真实模型返回的50字片段，另覆盖 Unicode 字符边界。

无数据超时后会通知连接清理器；Windows 的 socket shutdown 不一定立即唤醒底层等待，因此仍依赖有限的网络读取超时和最多4个连接的上限。回归同时检查清理信号、连接释放和保留真实超时错误。离线示例禁止发送补充改写，避免界面声称“未调用模型”而实际发起请求。

模型本次仍有需要人工判断的输出：语义与静态裁决不一致时转为 ASK；部分理由中的引用行号不准确。流式摘要只是预览，不能把模型自述的“已核实”作为独立事实证明。参考读取、完整模型输出、应用校验和用户采纳是不同步骤。
