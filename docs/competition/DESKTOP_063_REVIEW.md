# 0.6.3 保存、全文上下文与一键应用验收

2026-09-09。针对应用修改后保存入口消失、上下文过短以及缺少批量应用三项反馈。

## 修复

- 正文编辑区底部固定提供“保存到原文件”和“另存为”，应用修改、切换结果页或继续手动编辑都能使用。正文保存与修改稿保存明确区分内容来源；新文档未关联原文件时说明原因，仍可另存为。
- “检查上下文”显示可滚动的全文，自动定位当前变更，保留其他段落；可切换查看已采纳后的完整修改稿。逐条页继续显示带增删标记的 diff。
- “一键应用 N 条”将未拒绝的 REWRITE 应用到编辑区。已选择保留原文以及 ASK/VERIFY 涉及的文本不自动改写，磁盘文件不会自动覆盖。重叠建议使整个批次失败，并保留已有决定。
- 应用后可以撤销到应用前正文。开始新审查、打开其他文档或保存原文件后结束此次撤销记录，避免旧记录跨会话恢复。失效的保存确认明确报错，不回退为写入其他来源的正文。

## 回归与独立审查

旧代码下，真实 Vue setup 回归显示“应用后另存为”的桥接调用次数为0，测试失败。修复后通过。Cursor 只读审查指出撤销生命周期及失效确认问题；两项也先复现失败再修复。

前端46项测试通过，覆盖正文/修改稿内容来源、应用后导出、工作区/独立文件保存、连续保存校验值更新、批量排除拒绝与人工处理项、重叠原子性及撤销失效。桌面API、工作区写入与接口契约31项通过。此轮没有改动模型传输，不额外消耗模型请求。

## Windows 原生流程

在 `dist-0.6.3-review` 打包窗口实际操作：

1. 从首页运行无需密钥示例，进入逐条 diff，再打开全文上下文。标题、当前变更和后续两个段落均可阅读。
2. 一键应用1条改写，正文由78字符变为69字符；待补充和待核实对应的文字保持不变。正文底部仍显示保存入口与撤销按钮。
3. 经原生“另存为”生成测试文件，逐字节核对 UTF-8 内容及末尾换行。实际副本见 [导出证据](../../demo/evidence/native-063-bulk-export.md)。
4. 点击撤销，编辑区恢复78字符原文，磁盘副本保持不变。
5. 从原生打开对话框重新打开测试副本，手动追加“保存原文件验收。”，点击“保存到原文件”，确认目标路径及正文来源后保存成功。逐字节核对磁盘内容等于副本加手动输入，见 [原文件保存证据](../../demo/evidence/native-063-original-save.md)。

[原生界面记录](../../demo/evidence/native-063-save-flow.txt) 仅含虚构示例与目标应用文字。后续撤销生命周期和失效确认修复由回归与最终包独立复查覆盖。本轮原生流程为离线确定性验证，不宣称运行了新的真实模型请求。
