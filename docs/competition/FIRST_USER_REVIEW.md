# 首次使用者模拟体验记录

体验时间：2026-09-09（Asia/Shanghai）
对象：http://127.0.0.1:8765/，界面版本 0.5.0
方式：子 agent 从新浏览器标签页和空白首页开始，只操作 UI；没有先读源码、README 或其他 agent 的操作流程，也未调用外部模型。这是模拟首次使用者体验，不是真实人类用户研究。
窗口：实际截图为 1280 × 720。

## 整体感受

首页让我很快知道这是一款中文文档检查工具。空白区的“体验示例 · 无需密钥”是清楚的第一步，左侧正文、右侧检查结果的关系容易理解。示例加载后直接进入 Agent 过程，我能顺着“查看修改建议”完成逐条确认。整个演示无明显等待或卡死，过程显示约 0.1 秒、8 个步骤；因此看到的是完整记录，未实际感受到分阶段执行或实时等待。

成功走通了保留原文、撤销保留、采纳建议、全文核对、另存为和撤销采纳。预览只替换了采纳的第一句，另外两句待核实/补充的原文保持不变。默认不直接改正文、确认后才进入修改稿这点很清楚，给予我操作信心。

## 实际操作与可见证据

1. 空白首页展示“从一篇文档开始”“打开本地文件，或直接粘贴需要检查的中文内容”，主按钮是“体验示例 · 无需密钥”；底部显示“模型未配置”。截图已在本次浏览器工具记录中捕获。
2. 点击示例，左侧加载《文尺发布说明》，右侧自动显示 Agent 过程。提示“离线演示 · 使用本地规则和示例建议，无模型费用；真实语义复核请配置模型”。过程含“离线演示（模拟）…不调用模型”，以及本地扫描、REWRITE、VERIFY、ASK 的摘要。截图已捕获。
3. 点击“查看修改建议”：显示“0 已采纳 · 1 待确认 · 0 保留”，并说明只有采纳内容进入修改稿。唯一改写为“为了更好地提升用户体验，我们将会对系统进行优化。”→“我们将优化系统，改善用户体验。”
4. 点击“检查上下文”进入全文核对；上方显示变更上下文，下方是完整修改稿。未采纳时全文仍是原文。截图已捕获。
5. 点击“保留原文”：显示“0 已采纳 · 0 待确认 · 1 保留”“已保留原文”，出现“撤销决定”；再撤销，恢复 1 条待确认。
6. 点击“采纳建议”：显示“1 已采纳 · 0 待确认 · 0 保留”；完整修改稿第一句变为“我们将优化系统，改善用户体验。”；“另存为”“应用到正文”启用。
7. 点击“另存为”：未出现路径或命名输入界面，底部显示“已保存到 体验示例.revised.md”。这只证实 UI 成功反馈，未验证文件内容或实际保存位置。
8. 打开“复核结论”：说明“离线模拟演示已完成；这不是模型对文档的完整语义复核”；同时统计显示“1 处改写 · 2 处待人工处理 · 3 条模型新发现”“0 路模型调用”。依次打开待核实、待确认，能看到原文和缺少证据/负责人/截止时间的原因，“建议”内容为“—”。截图已捕获。
9. 返回修改稿，点击“撤销决定”撤销采纳：完整修改稿恢复原句，计数恢复“0 已采纳 · 1 待确认 · 0 保留”，“另存为”和“应用到正文”重新禁用。

## 发现的问题

### P2：离线模拟与“模型新发现”标签互相矛盾

复现：空白首页 → 体验示例 → 复核结论；或查看修改建议 → 检查上下文。

实际：演示顶部清楚说明不是完整语义复核、0 路模型调用，但统计写“3 条模型新发现”，三张结论均带“模型新发现”，全文核对也使用该标签。首次体验完成瞬间，底部还曾显示“语义复核完成：3 条结论，其中 3 条为模型新发现”。

影响：仔细阅读顶部后，我不会把它当作真实 AI 运行，但扫读卡片或截取局部画面的人容易误判建议来源。建议离线模式统一使用“示例建议/演示结论”，不要只在总提示中澄清。

### P3：全文核对的多层滚动削弱操作按钮可见性

复现：体验示例 → 查看修改建议 → 检查上下文，在 1280 × 720 窗口查看。

实际：右栏上半部的上下文和下半部完整修改稿各有独立纵向滚动条；上半部初始可见范围只到部分原文，采纳/保留按钮需要在该局部区域往下滚动。左侧同时还保留整篇原文。

影响：我能理解三个区域，但视觉重复，首次使用者容易先看到预览而遗漏决策操作。建议在全文核对时固定决策栏，或增加上下文区域高度。

### P3：另存为后的文件位置反馈不充分（不认定保存失败）

复现：采纳示例建议 → 点击另存为。

实际：仅底部短暂显示“已保存到 体验示例.revised.md”，没有可见目录、打开文件或下载入口，也未呈现命名/路径选择。

影响：从页面本身无法确认文件去了哪里；对“另存为”通常会选择名称和路径的预期也有差异。建议提示中说明下载/保存位置或提供可再访问的输出入口。文件是否真的保存成功尚未验证。

### P3：面向普通作者的界面仍有技术标签

实际可见：SEMANTIC_DEMO、Agent 过程、REWRITE / VERIFY / ASK 等。

影响：动作及原因中文说明足够理解，不构成阻碍，但 SEMANTIC_DEMO 并不帮助普通作者决定是否采纳。建议用户层优先呈现中文含义，技术来源收在详情。
