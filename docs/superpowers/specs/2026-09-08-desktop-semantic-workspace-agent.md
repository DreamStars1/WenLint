# 桌面语义复核与工作区 Agent

## 目标

1. 用户必须能区分“尚未运行语义复核”“复核失败”和“复核完成但无需修改”。
2. 语义复核并发执行静态候选裁决与全文独立发现，缩短组合任务的等待时间。
3. 全文独立发现必须能报告并安全应用正则规则未命中的新问题。
4. Windows EXE 可以关联用户主动选择的工作区，浏览并打开其中的文本文件，使用同一 Agent 审查，并在明确确认后写回。

## 安全约束

- API Key 只保留在进程内存，不进入正文、请求体日志或持久化配置。
- 模型不能直接提供最终修改稿；本地仅应用通过协议校验的 REWRITE `before` → `after`。
- 工作区操作只能访问所选根目录中的受支持文本文件；拒绝路径越界和符号链接，忽略依赖、版本库及构建目录。
- 其他工作区文件默认只向模型暴露相对路径索引，不发送正文。
- 写回文件需要独立确认，并以打开时的 SHA-256 阻止覆盖外部修改。

## 验收标准

- 没有静态候选时仍执行全文语义复核；零问题结果显示为已完成。
- 有静态候选时两个模型请求并发运行，每条候选恰好被裁决一次。
- 新问题使用 `finding_index=null`、`SEMANTIC_*` 规则和“模型新发现”标识。
- 结果展示完成时间、耗时、模型调用数和模型新发现数量。
- 工作区能够列出、筛选、打开受支持文件；未经确认、文件已变化或路径越界时拒绝写回。
